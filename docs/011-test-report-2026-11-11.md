## 已完成的功能

### Persona 路由机制

已实现并有测试覆盖：

1. 显式接受和推断接受时，在创建 Ticket 的事务中绑定 Persona。
2. Worker 首次请求注入精确的 Persona 快照；主 Session 不注入。
3. 支持 `off`、`fixed`、`random`、`rules` 路由模式。
4. 支持按 Worker 能力、任务特征和职责进行规则路由，并保留人工覆盖优先级。
5. 保存 Persona id、版本、注入文本、原因、路由器 id、首次 Assignment、Worker Session 和决定时间。
6. 同一 Ticket 并发启动、重试、Worker 重启、Host 重启、模板更新后复用首次绑定，不重新随机或重新决策。
7. 并发 Ticket 之间保持 Persona 快照隔离。
8. 未配置路由器或历史 Ticket 保持原生行为。
9. Ticket 详情页和管理 API 可以读取 Persona 审计信息。

## 完整套件失败的定位

已有失败主要属于当前 Windows 测试环境或跨平台边界，不应直接判定为 Persona 功能失败：

1. `runtime-concurrency.spec.ts` 的部分测试超时，涉及并发启动和 Worker 槽位。
2. `runtime.spec.ts` 的 Git 配置断言受 Windows 路径转义影响，实际内容为双反斜杠形式。
3. React/jsdom 测试出现重复 React 实例导致的 `Cannot read properties of null (reading 'useState')` / `useCallback`。
4. `service-script.spec.ts` 等测试无法 `spawn sleep`，因为当前 Windows 环境缺少 POSIX `sleep`。
5. 部分测试依赖 `sh`、`tmux`、`python3`、符号链接或 POSIX 文件模式；Windows 下会出现 `ENOENT` 或 `EPERM`。
6. 文档测试在 Windows CRLF 行尾下可能无法解析表格。

影响：当前环境可以可靠验证类型、构建、Persona 核心机制和隔离 fake-model e2e，但不能据此宣称完整跨平台测试套件全绿。需要在 Linux/WSL 的 Linux Node 环境中复跑依赖 POSIX 行为的测试。
